# 出口貿易業務系統（測試版）

使用 Python 3.12 與內建 SQLite，無需安裝第三方套件。

```sh
cd /workspace/FIRE-ALARM
python app.py
```

此本機模式僅監聽 127.0.0.1:8000，不含登入保護，不可直接公開。Render 部署須使用下方的 Gunicorn／WSGI 入口，提供登入保護。兩種模式皆為測試版本，尚無個別角色權限、外部電子簽章或會計整合，先使用假資料。資料及附件位於忽略追蹤的 `data/`，可用 `TRADE_DATA_DIR` 指定其他位置。程序停止後再備份整個資料目錄，勿只備份資料庫而遺漏附件。

## Render 線上測試部署

`render.yaml` 已準備一個 Python Web Service 與 1GB 持久磁碟。這是付費的 Starter 服務加磁碟；實際費用依 Render 確認畫面為準。此檔案不會自行註冊帳號或產生費用。不要改成免費、無磁碟方案後存放需要保留的資料。

1. 在 Render Dashboard 選擇 **New → Blueprint**，授權 GitHub 並選取 `rew201291-source/FIRE-ALARM` 的 `main` 分支。介面文字可能隨平台更新。
2. Render 讀取 `render.yaml` 後，設定 `APP_USERNAME`（自訂帳號）及 `APP_PASSWORD`（至少 16 字元的專用密碼）。只在 Render 的環境變數欄輸入密碼，不要貼到聊天或提交 Git。
3. 檢閱服務方案、磁碟與總費用，再自行確認建立。首次部署需安裝 `requirements.txt`。
4. 顯示 **Live** 後，使用服務頁上 Render 實際分配的 HTTPS 網址；以剛設定的帳密登入。不要使用 `python app.py` 作為公開服務指令。
5. 測試建立報價、確認文件、訂單、付款依據、採購、CI 及分次收款。重新部署後確認測試單據及附件仍在。

部署指令為：

```sh
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 60 'wsgi:create_application()'
```

Render 必須將持久磁碟掛載至 `/var/data` 並設定 `TRADE_DATA_DIR=/var/data/trade`；資料庫、登入工作階段及附件都位於此目錄。此架構使用單一執行個體，勿新增多個 replica 或 workers。`/healthz` 不需登入，僅檢查資料庫可讀。自動部署在 Blueprint 中關閉，更新需由管理者手動部署。

登入使用隨機工作階段，Cookie 設為 Secure、HttpOnly、SameSite=Strict，八小時到期；登出立即撤銷，變更帳密重啟後舊工作階段失效。整站登入嘗試合計每五分鐘最多十次。公開入口缺少有效帳密會拒絕啟動。此版本只有一組管理測試帳號，尚未提供每位同事的獨立帳號與操作稽核；不要作為正式財務系統。

### 資料備份

持久磁碟不等於獨立備份。正式導入前，需實作及演練資料庫、附件的一致性備份和還原。目前若要手動備份，停止 Web Service 後完整複製 `TRADE_DATA_DIR` 至另一儲存位置；不要刪除服務或磁碟作為停止方式。Render 當前帳號方案能否操作 Shell、匯出磁碟及使用快照，請依平台實際功能確認。原型不宣稱已完成備份或正式部署。

## 操作流程

1. 建立報價，填寫客戶、公司、商品、幣別、付款及交貨條件。
2. 上傳客戶回簽報價、客戶訂單或合約，再確認成單；自動產生應收紀錄。
3. 正式訂單擇一開立 PI 或 Sales Contract。
4. 設定付款期別，期限可填日期或「裝船前」等事件，合計須等於訂單金額。
5. 各期可登錄多次收款；銀行費用另列，客戶付款金額用於沖抵應收。
6. 訂單可關聯多張採購單與 CI；CI 的累計商品出貨數量不可超過訂單數量。
7. 單據可使用瀏覽器列印／另存 PDF，正式單據版面仍需依公司範本校對。

幣別支援 TWD、USD（兩位小數）、VND（整數）。各幣別分開統計，未提供跨幣別收款或匯差計算。後端金額使用 Decimal，資料庫保存十進位文字；前端彙總目前用於原型顯示。

## 已知限制

- 單據採保存快照，不提供編輯、作廢、退貨、退款或更正流程；付款排程在收款後鎖定。
- CI 使用出貨明細；英文大寫金額須人工輸入及確認。尚未建立獨立出貨／裝箱單模組。
- 合約條款需在報價建立時填入，未自動套用上傳的 Word 文件。
- 檔案以隨機名稱儲存並以下載方式提供；正式導入前仍需獨立帳號、角色權限、檔案掃描、稽核紀錄、備份與還原驗證。
- 上傳的三份文件為需求參考，未複製客戶銀行資料或原文件到 Git 儲存庫。
